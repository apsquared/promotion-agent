# The launch page

From Product Hunt's [Build your product page](https://help.producthunt.com/en/articles/17834537-4-build-your-product-page) guide, checked 2026-11-09. When `get_launch_context` reports composer limits, use those.

## Limits

| Field | Limit | Required to schedule |
| --- | --- | --- |
| Name | 40 characters | yes |
| Tagline | 60 characters | yes |
| Description | 500 characters | yes |
| First (maker) comment | 5,000 characters | recommended |
| Logo / thumbnail | 240×240 px recommended; JPG, PNG or GIF up to 2 MB on the website | yes |
| Gallery images | at least 1, three or more recommended; 1270×760 px recommended | yes (one) |
| Launch tags | up to 3 | yes (one) |
| Promo | offer text 25 characters, code 15 characters, optional end date | no |
| Shoutout note | 20 to 2,000 characters, once per product | no |
| Role | "I made this" (maker and hunter) or "I'm hunting it" | yes |

## Copy

- **Name**: the product name only. No tagline, no emoji.
- **Tagline**: what the product does, in plain words, for whom if it fits. No superlatives ("best", "ultimate", "revolutionary"), no hype, no buzzword stack. Test: could someone who has never heard of it say what it does after one read? Write three to five options and let the user pick.
- **Description**: lead with the value, then the features that deliver it; name the problem and the audience. Say why someone would pick it over the obvious alternative.
- **Relaunch copy**: the tagline, gallery and first comment are about the update, and credit the community feedback that shaped it.

## First comment

Pinned at the top of the discussion and posted when the launch goes live. Cover, briefly and in the maker's own voice:

1. who you are, and why you built it (the problem you hit);
2. what it does and who it is for;
3. what makes it different from what people use today;
4. one specific question you want feedback on;
5. the launch offer, if any.

Ask for feedback, never upvotes. Keep it short enough to read on a phone: a few short paragraphs and one list. Through the MCP it is HTML (`<p>`, `<ul><li>`, `<strong>`, `<a href>`), not Markdown. Draft it, then let the user rewrite it in their voice; people can tell a generic AI comment.

## Media

- **Thumbnail**: legible at small size. An animated GIF plays only on hover, so its first frame must work alone.
- **Gallery**: the product in use, not the logo. The first image carries the tagline's promise; then the main flow, the key differentiator, and proof (integrations, a result, a real quote you have permission to use). Readable text at gallery size, no tiny screenshots.
- **Video**: a short demo; it doesn't need polish. **Interactive demo**: a click-through that needs no signup. Both must be embeddable links.

## Everything else

- **Product link**: the direct page where people use or download the product, not a link shortener. For open source, the website first and the GitHub repository as an additional link.
- **Pricing**: Free, Free options or Paid; say honestly which.
- **Launch tags/topics**: the most specific ones that fit, up to three.
- **Makers**: every real teammate, each with their own personal account set up well before launch day, with a full profile (name, headline, website, socials). Company accounts can't launch or comment.
- **Offer**: one simple launch-only deal is fine. Feature it on the landing page too. It must never depend on an upvote.
- **Shoutouts**: tools that really helped build the product, chosen by the maker.
